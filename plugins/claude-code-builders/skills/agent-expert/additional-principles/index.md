# Additional Principles (Apply Based on Complexity)

These 9 principles apply beyond Core 4, based on instruction complexity. Apply them progressively as complexity increases.

| Complexity Level | Apply These Principles |
|-----------------|------------------------|
| **Multi-Step** | #8 (Dependencies), #10 (Acceptance Criteria), #14 (Examples) |
| **Complex** | #1 (Structured Formats), #2 (Format Spec), #8, #10, #14, #19 (Iterative), #20 (Capabilities), #21 (Execution Order) |
| **Mission-Critical** | All above plus #26 (Agent Audience) — apply all 26 principles comprehensively |

## Pages

- [Principle #1: Use Structured Formats](principle-1-structured-formats.md) — XML for complex multi-step workflows; markdown for simple sequences
- [Principle #2: Explicit Format Specification](principle-2-format-specification.md) — Output templates for investigation reports and structured data responses
- [Principle #8: State Dependencies Explicitly](principle-8-dependencies.md) — Use requires/prerequisite/blocks tags to make step ordering unambiguous
- [Principle #10: Comprehensive Acceptance Criteria](principle-10-acceptance-criteria.md) — Measurable pass/fail criteria with priority levels for every step
- [Principle #14: Positive AND Negative Examples](principle-14-examples.md) — Contrast clarifies boundaries; negative examples are disproportionately effective for LLMs
- [Principle #19: Iterative Frameworks](principle-19-iterative-frameworks.md) — Think/Act/Observe/Decide cycles for investigation-driven tasks
- [Principle #20: Specify Required Capabilities](principle-20-capabilities.md) — Describe WHAT capability is needed, not WHICH tool
- [Principle #21: Make Execution Order Explicit](principle-21-execution-order.md) — Sequential and parallel execution patterns
- [Principle #26: Design for Agent Audience](principle-26-agent-audience.md) — Executable protocols over conversational prose
